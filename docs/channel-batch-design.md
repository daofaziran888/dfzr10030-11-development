# 通道接入批次包：设计取舍记录

日期：2026-11-18
涉及模块：数据接入通道（ingestion，写入方）、格式解析器（parser，读取方）
领域代码：`backend/app/services/channel_batch.py`

## 1. 要解决的问题

三种输入格式（JSON / CSV / XML）的数据同时进入不同接入通道，原页面只能看到通道状态，
无法核对每一批数据由哪些通道、哪些格式的分片组成。缺少把多输入通道合并成可核对批次的产物，
且必须保证格式解析服务不会收到“无法解释的混合数据”。

## 2. 服务边界定位（跟着接入通道服务取数逻辑）

| 边界 | 归属 | 职责 | 对批次包的权限 |
| --- | --- | --- | --- |
| 接入通道服务 | `services/ingestion.py` + `routers/ingestion.py` | 分片登记、切批预演、整组构建 | 写入（同动作同步更新通道缓冲队列） |
| 领域规则 | `services/channel_batch.py` | 切批算法、背压判定、版本控制、快照组装 | 无路由，只被两侧服务调用 |
| 格式解析服务 | `services/parser.py` + `routers/parser.py` | 按批次选字段映射、审核、编排 | 只读同一份批次包 + 回写工作台项 |

关键取舍：**不做两个服务各存一份**。两侧通过内存仓库中同一张 `ingestion_batch` 表共享，
构建动作在同一个锁、同一次调用里完成批次写入、分片状态回写、工作台项生成和通道队列刷新，
天然满足“同一个动作同时更新两边、两边读取同一份”。

## 3. 两个合并边界的比较

冲突场景：同一通道缓冲队列接近背压阈值时，两个不同格式的分片同时到达，
构成同一数据链上的冲突。两种方案都是合法边界，批次包结构确实不同，页面提供预演对比。

### 方案 A：`channel_first` 按通道合并、阈值处切开（背压边界前置）

- 做法：按通道队列序号顺序消费，遇到输入格式切换或累计大小将超背压阈值即切新批次。
- 前置决定因素：背压边界先决定切断位置，格式切换只是同一切批循环里的另一个切断条件。
- 优点：切断点与队列水位一一对应，背压语义最直接；批次数量较少、实现直接；
  每批的“队列累计/阈值”在背压快照里可逐批核对。
- 缺点：同一格式的分片可能被相邻的其他格式分片打散到多个批次。

### 方案 B：`format_first` 按输入格式分别成批、再汇总通道批次（输入格式前置）

- 做法：先按输入格式拆成保持首次出现顺序的子队列，各子队列内部再按背压阈值成批，
  leaf 之上挂通道汇总批次，多通道再挂整组批次。
- 前置决定因素：输入格式先决定子批次结构，背压阈值在各格式子队列内部生效。
- 优点：同格式分片尽量聚合，解析端选映射更集中；子批次结构直接体现格式维度。
- 缺点：批次数量通常更多；同格式累计仍可能超阈值，此时照样在阈值处切开
  （例如 JSON 60 + JSON 55 在阈值 100 下仍是两个 leaf，不能合并成 115）。

### 共同的硬底线（比较后的最终取舍）

1. **背压完整优先于一切聚合意图**：单分片超过通道背压阈值直接置「超限拦截」，
   任何策略都不允许它进入完成批次；同格式累计超阈值也必须切开。
2. **leaf 批次输入格式单一且通道可追溯**：混合格式只允许出现在 channel/group 汇总层，
   解析端只读 leaf，因此永远不会收到无法解释的混合数据。
3. 每个 leaf 固化通道快照与背压快照（队列水位、阈值、是否超限、切断点累计值），
   使每批输入都能追溯到通道、格式和背压状态的数据快照。

结论：默认策略取 `channel_first`（背压控制直接、批次数量较少），
但两种策略都在产品中保留并可预演；取舍结果不改变硬底线。

## 4. 其他规则落点

- **多选整组 + 逐台记录**：构建按通道串行处理，每台独立成功/失败并写入构建记录；
  一台没有可成批分片不影响其他台产出，多通道额外生成 group 汇总批次。
- **同版本仅一次成功**：进程内 `RLock` 串行化 + 数据版本唯一校验。
  显式传入已存在版本直接拦住；自动版本号取该通道未占用的最小 `vN`，
  因此种子里的历史版本 `INGE-0003@v1` 不会被复用。并发提交用屏障压测验证仅一次成功。
- **历史不变、按适用范围重算**：构建只消费「待入批」分片，已入批分片与历史批次永不重算；
  通道背压阈值变更后，新阈值只作用于之后登记/构建的分片，历史批次快照保留旧阈值与旧大小。
- **工作台同步**：每个 leaf 落库时同步生成一条待审核工作台项，按输入格式匹配解析配置；
  未审核通过不能编排，审核与编排都不可重复执行。
